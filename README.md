# Fitness Tracker

Учебный проект (итоговая практика по React). Тема №33: дневник тренировок.
Пользователь регистрируется, записывает свои тренировки (упражнение, дата, подходы, повторы, вес) и видит прогресс. Тренировки всех пользователей доступны для просмотра в общем списке.

## Возможности

- Регистрация, вход, выход, сохранение сессии после обновления страницы
- Личный кабинет: создание, редактирование и удаление своих тренировок (удаление с подтверждением)
- Публичный список тренировок с поиском и страница отдельной записи
- Страница «Обзор»: рецепты из внешнего API (DummyJSON /recipes) с поиском, сортировкой по калориям и состояниями загрузки, ошибки, пустого результата и «Повторить»
- Защищённые маршруты: гость перенаправляется на `/login` и после входа возвращается на нужную страницу
- Адаптивный интерфейс (тёмная тема)

## Стек

React, React Router, Vite, Tailwind CSS, Supabase(аутентификация и база PostgreSQL).

## Структура

```
src/
  components/   Layout, ProtectedRoute, WorkoutCard, WorkoutForm, ConfirmModal, Loader, ErrorMessage, EmptyState
  context/      AuthContext (пользователь, вход, регистрация, выход, восстановление сессии)
  hooks/        useLoad (загрузка данных со состояниями loading / error / повтор)
  pages/        страницы сайта
  services/     supabaseClient, workoutsApi (CRUD), externalApi (внешний API), errors
  styles/       index.css (Tailwind и цвета темы)
supabase/
  schema.sql    таблица workouts и правила доступа (RLS)
```

## Запуск

1. `npm install`
2. Создать проект в Supabase, выполнить `supabase/schema.sql` в SQL Editor, в настройках Authentication выключить Confirm email.
3. Скопировать `.env.example` в `.env` и вписать `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` (Project Settings → API).
4. `npm run dev`, сайт откроется на `http://localhost:5173`.

Файл `.env` в репозиторий не добавляется.

## Маршруты

| Маршрут               | Доступ          | Описание                                 |
| --------------------- | --------------- | ---------------------------------------- |
| `/`                   | все             | Главная: описание и последние тренировки |
| `/workouts`           | все             | Список тренировок с поиском              |
| `/items/:id`          | все             | Страница одной тренировки                |
| `/explore`            | все             | Данные из внешнего API                   |
| `/login`, `/register` | все             | Вход и регистрация                       |
| `/dashboard`          | вошедшие        | Мои тренировки, изменение и удаление     |
| `/dashboard/new`      | вошедшие        | Новая тренировка                         |
| `/dashboard/edit/:id` | владелец записи | Редактирование                           |
| `*`                   | все             | Страница 404                             |

## Хранение данных и доступ

Данные хранятся в PostgreSQL (Supabase), после обновления страницы и перезапуска они остаются.
Пароли хранит система аутентификации Supabase (в открытом виде не хранятся), сессия восстанавливается после перезагрузки.

Права проверяются на стороне базы данных правилами Row Level Security (`supabase/schema.sql`):

- читать записи может любой посетитель;
- создавать запись может только вошедший пользователь и только от своего имени;
- изменять и удалять запись может только её владелец. При попытке изменить чужую запись база ничего не меняет, сайт показывает сообщение об отсутствии прав.

Роль администратора в проекте не реализована.

## Внешний API

DummyJSON, `GET https://dummyjson.com/recipes?limit=20`. Используются поля name, image, caloriesPerServing, prepTimeMinutes, cookTimeMinutes, cuisine. Данные показываются как идеи питания для набора массы и восстановления после тренировок. DummyJSON хранит изменения только для GET, поэтому весь CRUD сделан на собственной базе в Supabase.
